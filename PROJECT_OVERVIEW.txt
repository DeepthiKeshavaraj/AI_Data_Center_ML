1. EXECUTIVE SUMMARY & PROJECT GOAL
The objective of this project is to develop an integrated machine-learning
framework for intelligent AI data center management.

In traditional data centers, workload scheduling, thermal management, and 
network security are investigated as separate, isolated domains. This project
unifies them under a common operational decision-making framework:

  Workload Demand  ──> Power & Temperature  ──> Dynamic Cooling  ──> Node Availability
  Network Traffic  ──> Feature Extraction   ──> Threat Detection ──> Threat Isolation
                                    ↓
              Unified Resource & Scheduling Decision Platform

The prototype is implemented directly inside the existing workspace with NO
fabricated metrics, NO fake predictions, and full preservation of existing
research code and datasets.


2. MACHINE LEARNING (ML) IMPLEMENTATION BREAKDOWN

A. NETWORK SECURITY THREAT INTELLIGENCE (LIVE & DEPLOYED)
   * Model Type: Random Forest Classifier (200 trees, balanced class weights).
   * Feature Pipeline: ColumnTransformer with SimpleImputer (median for numeric,
     most-frequent for categorical) and OneHotEncoder(handle_unknown='ignore').
   * Exact 8 Input Features:
       1. flow_duration    (Numeric, seconds)
       2. src_packets      (Numeric, packet count)
       3. dst_packets      (Numeric, packet count)
       4. src_bytes        (Numeric, byte count)
       5. dst_bytes        (Numeric, byte count)
       6. protocol         (Categorical, e.g., tcp, udp, ospf, arp)
       7. connection_state (Categorical, e.g., fin, con, int, req)
       8. service          (Categorical, e.g., -, http, dns, ftp, smtp)
   * Preprocessing Script:
       src/preprocessing/prepare_security_ml.py
       Extracts standardized features from raw/standardized CSVs into ml_ready.csv.
   * Training Script:
       src/scripts/train_security_baseline.py
       Fits pipeline on 175,341 training flows and exports serialized artifact:
       ==> models/security/security_random_forest.joblib
   * Target Output:
       Binary classification: 0 (Normal) vs. 1 (Attack) with calibrated probabilities.
   * Verified Evaluation Results (from reports/security_model/):
       - Training Rows: 175,341 flows (UNSW-NB15 Standardized)
       - Holdout Testing Rows: 82,332 flows
       - Test Accuracy: 88.36% (0.8836)
       - Balanced Accuracy: 87.57% (0.8757)
       - ROC-AUC Score: 0.9721
       - Attack Recall: 95.3% (43,203 out of 45,332 attacks detected)
       - Attack Precision: 85.3%
       - Normal Precision: 93.3%
   * Unseen Feature-Combination Evaluation (src/scripts/evaluate_unseen_security.py):
       - Evaluated on 47,089 holdout flows having zero feature overlap with training data.
       - Accuracy on Unseen Flows: 82.49% (0.8249)
       - ROC-AUC on Unseen Flows: 0.9384
       - Qualification: Demonstrates model resilience across novel combinations
         of known features in the benchmark holdout set (not an absolute zero-day guarantee).
   * Feature Importance Ranking (src/scripts/security_feature_importance.py):
       1. flow_duration    : 22.7%
       2. src_bytes        : 19.3%
       3. dst_bytes        : 13.8%
       4. connection_state : 13.0%
       5. dst_packets      :  9.6%
       6. src_packets      :  9.4%
       7. protocol         :  6.6%
       8. service          :  5.6%

B. WORKLOAD INTELLIGENCE & CLUSTER ALLOCATION (SIMULATION ACTIVE)
   * Offline Training Architecture:
       Script: src/models/workload/train_workload_model.py
       Target: next_machine_cpu (%)
       Features: machine_cpu, machine_gpu, machine_cpu_usr, machine_cpu_kernel,
                 machine_cpu_iowait, machine_load_1, machine_num_worker.
       Split: Chronological holdout (latest 20% of observations per node).
       Documented Benchmark Metrics:
         - Random Forest Regressor (100 estimators, max depth 18):
           MAE: ~1.546 %, RMSE: ~3.153 %, R²: ~0.971
         - Persistence Baseline: ŷ(t+1) = y(t).
   * Ingestion Status:
       The multi-gigabyte pai_machine_metric.csv source file was omitted from Git.
       Per project rules, live regression inference is disabled (returns HTTP 503
       with clear explanation) rather than substituting fake predictions.
   * Cluster Allocation Simulation Engine:
       Uses authentic Alibaba PAI server specifications:
       ==> src/data/raw/workload/pai_machine_spec.csv (1,897 physical server nodes)
       The simulator accepts user demand (CPU cores, Memory GB, GPU count), applies
       the chosen placement strategy (Balanced Distribution, Bin Packing, or GPU
       Node Prioritization), enforces an 85% safety capacity ceiling per node, and
       calculates before-and-after cluster utilization.

C. THERMAL MANAGEMENT & RISK FORECASTING (ARCHITECTURE DOCUMENTED)
   * Forecasting Architecture:
       Script: src/models/thermal_forecasting.py
       Horizon: 30 minutes ahead (3 steps of 10-minute intervals).
       Target: mean_outlet_temp (°C)
       Features: 30-minute historical lag features (0, 10, 20, 30, 60 min) across
                 mean_inlet_temp, mean_outlet_temp, mean_power_consumption,
                 and mean_temperature_difference.
   * Exploratory Thermal Risk Criteria:
       Script: src/models/thermal_risk_analysis.py
       Statistical thresholds evaluated on Marconi A2 supercomputer logs:
         - 55.0 °C : Advisory (Elevated zone; inspect CRAH fan airflow)
         - 60.0 °C : Warning (Action threshold; inspect containment panels)
         - 65.0 °C : Critical (Workload throttling and fan speed ramp)
         - 70.0 °C : Emergency (Hardware safety thermal shutdown limit)
         - 95th Percentile Cutoff : Statistical peak events.
   * Ingestion Status:
       Multi-GB raw sensor telemetry was omitted from Git. The UI features a
       User-Provided Scenario Explorer and statistical threshold documentation,
       while suppressing fake predictions.


3. SOFTWARE ARCHITECTURE (FULL-STACK PROTOTYPE)

   Located in: backend/

   * app/api/endpoints.py: REST routing for 24 endpoints (including authentication and simulation).
   * app/services/:
       - db.py                 : MongoDB Atlas connection pool, unique email index, and mongomock testing fallback.
       - auth_service.py       : RFC 9106 Argon2id password hashing, session management, and HttpOnly cookies.
       - model_loader.py       : Singleton registry tracking real artifact existence.
       - security_service.py   : Preprocessing & live inference for Random Forest.
       - workload_service.py   : Machine spec parser & heuristic allocation engine.
       - thermal_service.py    : Thermal feature metadata & threshold definitions.
       - simulation_service.py : Cross-domain dependency engine, presets, and rule evaluation.
       - dataset_service.py    : Allowlist-controlled dataset sampler & summarizer.
   * app/schemas/: Strict Pydantic models for authentication, users, models, simulation, and datasets.
   * tests/: 28 automated test cases (pytest) covering health, authentication, Argon2id hashing,
     sessions, models, inference, presets, cross-domain propagation, and dataset sampling.
     ==> 100% test pass rate in 10.73s.

5. HOW TO RUN THE APPLICATION
The backend and frontend servers run independently in local development mode:

Terminal 1: Start Backend API (FastAPI)
  cd AI_Data_Center_ML
  python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
  Health Check: http://127.0.0.1:8000/api/health
  Swagger API Docs: http://127.0.0.1:8000/docs

Terminal 2: Start Frontend (React + Vite)
  cd AI_Data_Center_ML/frontend
  npm run dev
  Web Dashboard: http://localhost:5173/ (or http://127.0.0.1:5173/)

Run Test Suites:
  Backend Tests:  python -m pytest backend/tests/test_api.py -v
  Frontend Build: cd frontend && npm run build
